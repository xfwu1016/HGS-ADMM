# Data provenance and preprocessing

## Access

All simulation samples are generated by the included scripts. Both public datasets are loaded from files shipped with the installed scikit-learn package, using `load_diabetes` and `load_breast_cancer`; there is no remote dataset fetch in the experiment pipeline. Installing dependencies can require network access. A fully offline run is possible once the Python environment is installed; see [ENVIRONMENT.md](ENVIRONMENT.md).

| Dataset | Loader and original source | Local processing |
|---|---|---|
| Diabetes: 442 observations, 10 original features | [`load_diabetes`](https://scikit-learn.org/1.8/modules/generated/sklearn.datasets.load_diabetes.html); Efron et al., *Least Angle Regression*, [doi:10.1214/009053604000000067](https://doi.org/10.1214/009053604000000067) | Raw features (`scaled=False`), degree-two expansion without a bias column, training-fitted scaling, Huber elastic-net model |
| Wisconsin Diagnostic Breast Cancer: 569 observations, 30 features | [`load_breast_cancer`](https://scikit-learn.org/1.8/modules/generated/sklearn.datasets.load_breast_cancer.html); [UCI dataset and attribution](https://archive.ics.uci.edu/dataset/17/breast+cancer+wisconsin+diagnostic), [doi:10.24432/C5DW2B](https://doi.org/10.24432/C5DW2B) | Stratified partition, training-fitted feature scaling, signed labels with benign as the positive class, logistic elastic-net model |

The scripts do not redistribute a separate copy of the raw datasets. Dataset attribution and access terms remain those of their original sources and scikit-learn's dataset documentation.

## Splits and model selection

`code/run_experiments.py` defines the original public-data experiment. It reserves 30% for testing, divides the remaining training data into fit and validation subsets for tuning, then refits preprocessing on the full training set. Scaling and tuning do not use that split's held-out test observations. The selected parameters, tuning scores, split indices, feature scaling and response scaling are saved by the run in `results/cases.json` and `results/datasets/`.

`code/repeated_real_splits.py` uses seeds **2026–2030** for both datasets. Diabetes has five configurations per seed: a `1×1` reference, unit/budget `4×1`, and unit/budget `4×4`. Breast cancer has three configurations per seed: a `1×1` reference and unit/budget `4×1`. The total is **40 fitted records**, not 40 independent random splits.

Diabetes uses split-specific validation selection. Breast-cancer repeats fix `lambda = 0.001`, selected on the original 2026 validation split. Later test partitions can overlap that earlier validation subset. These repeated fits compare optimizer behavior for a fixed objective; the breast-cancer predictive summaries are descriptive optimizer-agreement checks, not an independent estimate of a newly tuned procedure's generalization performance.

The TCP study uses the same data-preparation routines: Diabetes LAN has five paired split seeds; Diabetes WAN and breast-cancer LAN use seed 2026. Unit and budget runs form the pairs. This gives **14 complete process-level runs**.

## Simulations and saved outputs

Synthetic study generators and seeds are explicit in `code/run_experiments.py` and the additional study scripts. The main simulation has 300 training observations and 600 features, with five seeds for each of squared fused, Huber and logistic regression. Additional calibration and diagnostic designs are defined by their own scripts; the full entry point runs them in dependency order.

Fresh `--all` execution creates its own processed public-data splits, coefficients, iteration traces and records. No archived result is needed as an input before the sequence begins. Preserve those outputs if you want to regenerate numerical tables or figures later; summary CSV files alone are insufficient for every diagnostic.
